# 容器首次启动修复与验收报告

日期：2026-09-30（Asia/Shanghai）。范围：仅 passenger-flow-docker；原 passenger-flow-system-codex 未修改。源码留在原目录，不打包、不提交、不推送。

## 1. 结论与当前使用方式

本轮 Windows＋Docker Desktop 独立验收通过。当前 http://127.0.0.1:3031 可访问，APP和数据库容器均已通过健康检查。普通3030旧环境没有被自动重设密码；旧卷恢复不是本轮成功判定的一部分。

1. 新电脑首次双击 start-docker-acceptance.bat，按引导配置；已有当前验收环境可直接访问3031。
2. 双击 show-docker-acceptance-config.bat，仅在本机查看网页登录 APP_AUTH_USER / APP_AUTH_PASSWORD。
3. 双击 verify-docker-acceptance.bat 检查；stop-docker-acceptance.bat 停止但保留数据。

本机默认数据库 passenger_flow_codex、数据库业务账号 passenger_app、网页账号 local-admin。密码是本机引导设置/独立生成，三类密码不能互换，本文不记录密码。本地APP使用服务名db:3306，不抓取或回写容器IP。

- Compose按服务名解析容器地址，容器重建不需要保存IP：[Docker官方说明](https://docs.docker.com/compose/how-tos/networking/)。

- 已存在数据目录不因初始化环境变量改变账号：[官方MySQL镜像说明](https://github.com/docker-library/docs/blob/master/mysql/README.md)。
- 依赖修复版本参考：[brace-expansion维护者公告](https://github.com/advisories/GHSA-q2hr-2g5m-vwhr)。依赖告警不等于已经证实业务路由可被利用；npm审计0不代替镜像及云端安全验收。

## 5. 云端部署、回退与未验证边界

1. 准备TencentDB私网端点、库与业务账号，Secret分别保存数据库和网页登录密码；不使用本机root作为云端应用账号。
2. 新源库用一次性Job建表（需要演示资料时仅Job显式SEED_DEMO_DATA=true），等待Job Complete成功后才创建Deployment；DTS目标端不运行该Job。
3. 两个应用Pod的AUTO_INIT_SCHEMA/SEED_DEMO_DATA保持false；只读预检查、数据库和八表成功后应用才监听。
4. 通过受控port-forward检验两个Pod、认证、页面和数据库负载，再接入监控；手动发布要求TCR不可变标签已实际启用并确认。
5. 本次未推送TCR、未连接TKE/TencentDB、未修改云资源。腾讯云网络、TLS、调度、Prometheus、双副本滚动发布与回退，以及MariaDB10.3.39和VMware/Rocky实机均未在本轮重测。

回退：本地保留上一已验收镜像摘要、所选配置和卷；停止APP后按原摘要及原配置启动，先验证再访问，不删除卷、不自动降级数据库引擎。TKE通过rollout undo回退APP镜像，不能回退数据库DDL、客流或DTS进度。本次没有自动改密/清库，旧3030卷密码问题需恢复原配置或单独由管理员处理。
